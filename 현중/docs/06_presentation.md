## 3. 왜 이 모델인가 (1분)

토크나이저를 dev 1,500건에 직접 돌려 비교했다. **점수가 아니라 "정답을 복원할 수 있는가"로 골랐다.**

| 토크나이저 | UNK 비율 | UNK 포함 대화 | 정답 되살림 |
|---|---:|---:|---:|
| **pko-t5-base** | **0%** | **0%** | **99.73%** |
| ke-t5-base | 1.02% | 56.2% | 97.53% |
| mt5-base | 0.34% | 30.7% | 99.13% |

- `ke-t5`는 구어체 글자(`걍`, `넹`, `앜`)가 UNK가 되어 **정답 문장조차 복원하지 못한다** (`쌩쌩하다` → `하다`). 복원 못 하는 표현은 생성도 못 한다
- `mt5`는 vocab 250k라 임베딩만 1.9억 파라미터 — 8GB VRAM에 불리
- 팀 내 다른 실험(Codex)이 KoBART 계열이라, **모델 계열부터 다르게 가서 독립적인 비교군**을 만들었다

## 4. 어떻게 실험했나 — 규모를 단계적으로 (2분)

작게 시작해 근거가 있을 때만 키웠다. 모든 비교는 **한 번에 한 변수**, 판정은 **paired bootstrap 95% 구간**.

### 4.1 Stage 0 — 파이프라인이 맞는가 (64건, 2분)

64건만 40 epoch 외우게 해서 **재현 ROUGE-L 97.98** (기준 90). 데이터 로딩·라벨 마스킹·EOS·생성·점수 계산이 정상이라는 근거.
이 단계가 있어야 이후 점수가 낮을 때 "버그"와 "성능"을 구분할 수 있다.

### 4.2 Stage A — 입력 형식 결정 (2,000건 × 4 run, 50분)

| 비교 | 결과 (dev ROUGE-L space) | 판정 |
|---|---|---|
| 직렬화 `plain` vs `speaker` | +0.20 [−0.39, +0.78] | **차이를 확인하지 못함** |
| 직렬화 `turn` vs `speaker` | −0.25 [−0.87, +0.37] | **차이를 확인하지 못함** |
| 시스템 태그 `type` vs `drop` | +0.11 [−0.40, +0.64] | **차이를 확인하지 못함** |

→ 셋 모두 유의한 차이를 확인하지 못해 기준(`speaker`/`drop`)을 유지했다.
**"유의한 차이를 확인하지 못했다"도 결과다.** 점수 차이만 보면 `plain`이 좋아 보이지만 구간이 0을 포함한다.

### 4.3 Stage B → C — 규모 확대 (20,000 → 278,292건)

| 단계 | 학습 건수 | dev ROUGE-L space | 이전 대비 (95% CI) | 학습 시간 |
|---|---:|---:|---|---:|
| A | 2,000 | 22.63 | — | 12.5분 |
| B | 20,000 | 25.16 | **+2.53 [+1.80, +3.23]** | 38분 |
| C | 278,292 | 27.33 | **+2.17 [+1.36, +2.87]** | 371분 |

→ 두 단계 모두 구간이 0을 넘었다. **규모 확대를 포함한 단계 변경 후 ROUGE 개선을 관찰했다.**
(주의: A→B는 epoch도 3→2로 함께 바뀌었다. 데이터만의 효과로 말하지 않는다)

### 4.4 epoch를 더 늘리면? — 아니었다 (6시간 12분)

Stage C가 마지막 평가에서 best였기 때문에 3 epoch를 시도했다.
결과: **−0.06 [−0.57, +0.45]**, 차이를 확인하지 못함. 1 epoch 이후 27 근처에서 정체했다.
이 설정에서 추가 이득을 확인하지 못해 보류했다. 학습률 스케줄이 원인인지는 분리 검증하지 않았다.

## 5. 최종 결과 (1분)

**test = 공식 valid 35,004건, 최초이자 유일한 1회 평가** (`artifacts/eval/TEST_USED.json`으로 잠금)

| 평가셋 | 건수 | ROUGE-L space [95% CI] | ROUGE-L morph [95% CI] | 규칙 기반 자동 점검 통과율 (정답) |
|---|---:|---|---|---|
| dev | 1,500 | 27.46 [26.47, 28.42] | 45.29 [44.44, 46.10] | 97.3% (94.3%) |
| **test** | **35,004** | **27.15 [26.95, 27.36]** | **45.35 [45.16, 45.54]** | **97.0% (95.2%)** |

- dev와 test의 95% 구간은 겹치지만, dev 평균은 test 구간 밖이다. 평균 차이만으로 과적합의 유무를 확정할 수 없다
- 참고선: 가이드라인 시범 모델 ROUGE-L 19.547 — 단, 원문에 토큰화 기준이 없어 **비교가 아니라 참고**다
- 출력 태그 0건, 빈 출력 0건, 반복 4-gram 예측 7.1% (정답 6.2%)

**같은 점수도 기준에 따라 다르다**: 공백 27.15 vs 형태소 45.35. 한국어는 조사·어미 때문에 공백 기준이 가혹하다.
그래서 이 프로젝트는 항상 두 기준과 디코딩 설정(beam 4)을 함께 적는다.

## 6. 무엇을 못 하는가 (1분) — 발표에서 가장 중요한 부분

### 6.1 토론 대화 형식을 못 배웠다

| 항목 | 모델 | 정답 |
|---|---:|---:|
| "토론" 문자열 포함 (test 188건; 형식 전체 미검증) | **4.8%** | 100% |
| ROUGE-L space | **16.02** | (일상 대화 27.21) |

원인 가설 (미검증): 학습 데이터의 0.574%뿐이고, **입력에 대화 유형 정보가 없다**. 모델이 내용만 보고 토론임을 알아내야 한다.

### 6.2 사실 오류가 남아 있다 (dev 고정 100건, Claude 판정)

| 유형 | 건수 | 95% 구간 |
|---|---:|---|
| 무난 | 67 | 57.3 ~ 75.4% |
| **사실 오류 (Claude 판정)** | **15** | **9.3 ~ 23.3%** |
| 핵심 누락 | 13 | 7.8 ~ 21.0% |
| 화자 혼동 | 7 | 3.4 ~ 13.7% |
| 형식 위반 | 1 | 0.2 ~ 5.4% |

오류가 하나 이상인 요약이 **33/100**이다. 무난한 요약의 ROUGE-L은 평균 29.6, 오류가 있는 요약은 15.4다.

- 사실 오류 예: 대화에서는 **에어컨** 때문에 추운데 요약은 "날씨가 추워져서 에어컨이 센 것 같다"로 **인과를 뒤집었다**
- 화자 혼동 예: 우산을 두고 온 사람과 "비 와서 싫다"는 사람을 한 주체로 합쳤다
- **그래서 "최종 모델 확정"이라고 부르지 않는다.** 100건으로 늘려 구간을 좁혔지만(22%p → 14%p), 판정자는 여전히 Claude 1인이다

### 6.3 긴 대화일수록 약하다 (test, ROUGE-L space)

짧은 대화 30.88 → 중간 27.33 → 긴 대화 23.27. 0.34%는 train 잘림 비율이며 test 길이별 잘림과 오류의 관계는 미측정이다. **원인은 확인하지 않았다.**

### 6.4 ROUGE 자체의 한계

ROUGE-L이 0인데 내용은 맞다고 Claude가 판정한 요약이 100건 중 3건 있었다. 정답과 **다른 부분**을 요약하면 점수가 0이 된다.
그래서 ROUGE 단독으로 판단하지 않고 자동 점검 통과율·오류 분류를 함께 본다.

## 7. 이 프로젝트에서 지킨 규칙 (30초)

발표에서 "어떻게 일했는가"로 쓸 수 있는 부분.

1. **한 번에 한 변수만** 바꾼다. 불가피하게 둘이 바뀌면 그렇게 기록한다 (A→B의 epoch 변화)
2. 차이는 **95% 구간**으로 말한다. 구간이 0을 포함하면 "차이를 확인하지 못했다"고 쓴다
3. 토큰화 기준과 디코딩 설정을 **항상 함께** 적는다. beam 4 → 1로만 바꿔도 1.6점이 움직인다
4. **test는 1회.** 코드로 잠갔다
5. 확인하지 않은 것은 확인하지 않았다고 쓴다 (예: 학습 직후 평가와 평가 스크립트의 0.13점 차이 — 원인 미확인)
6. 결정마다 **근거 등급**을 붙였다: A 측정 / B 관찰 / C 관행 (`05_decisions.md`)

## 8. 다음에 할 일 (30초)

| 후보 | 비용 | 기대 |
|---|---|---|
| **사람**이 하는 오류 판정 | GPU 불필요 | **1순위.** 지금 판정자는 Claude 1인이다. 사람 판정과 얼마나 다른지 모른다 |
| weight decay / 이모티콘 태그 / 학습 seed | run당 약 40분 | 직접 비교 또는 반복 검증이 남은 항목 |
| 토론 형식 개선 | Stage C 재학습 6시간 | 유형 표시로 1.5%→19.5%. 더 올리려면 데이터가 필요 |

**2026-09-20에 검증을 끝낸 것** — 관행으로 정했던 값들을 실제로 비교했고, **일부 비교에서 기준값이 높았고 나머지는 차이를 확인하지 못했다.**

| 비교 | 결과 (dev ROUGE-L space, 95% CI) | 결론 |
|---|---|---|
| 학습률 3e-4 | −0.31 [−0.96, +0.37] | 차이 미확인 |
| 학습률 5e-5 | **−0.93 [−1.44, −0.41]** | 더 나쁨 |
| 유효 배치 8 | +0.18 [−0.27, +0.65] | 차이 미확인 (학습 시간 1.6배) |
| 유효 배치 32 | **−0.87 [−1.40, −0.40]** | 더 나쁨 |
| warmup 0% / 10% | −0.22 [−0.62, +0.13] / −0.04 [−0.41, +0.31] | 차이 미확인 |
| label smoothing 0.0 | −0.41 [−0.87, +0.01] | 차이 미확인 (반복은 증가) |
| 정규화 축약 끄기 | −0.21 [−0.74, +0.30] | 차이 미확인 (입력만 길어짐) |
| length_penalty 1.2 / 0.8 | −0.01 [−0.22, +0.22] / **−0.44 [−0.71, −0.17]** | 차이 미확인 / 더 나쁨 |
| epoch 3 | −0.06 [−0.57, +0.45] | 차이 미확인 |

→ 발표 포인트 세 가지
1. **"기본값이 운 좋게 맞았다"가 아니라 "9종을 확인해 보니 바꿀 이유가 없었다"**를 수치로 말할 수 있다. 기준값이 더 나은 것으로 확인된 경우가 3건(lr 5e-5, 유효 배치 32, lp 0.8)이다
2. lr 3e-4는 **train loss가 가장 낮은데 ROUGE는 낮았다.** loss 개선 = 성능 개선이 아니다
3. 문장 bootstrap 구간은 고정된 예측의 평가 표본 변동만 반영한다. 학습 seed 변동·반복적인 dev 탐색·판정자 오차는 별개이며, 유의성 미확인은 동등성 입증이 아니다. 차이의 구간 폭은 비교하는 예측 쌍마다 달라 고정된 ±0.6점 판별 한계는 없다.

### 유형 표시 실험 결과 (2026-09-20, Stage B 규모 40분)

입력 앞에 `[토론]` / `[일상]`을 붙여 학습했다. 변수는 이것 하나.

| 평가셋 | 기준선 | 유형 표시 | 차이 (95% CI) |
|---|---:|---:|---|
| dev 1,500 (ROUGE-L space) | 25.16 | 25.26 | +0.11 [−0.40, +0.62] → 차이 미확인 |
| **dev_debate 200 (ROUGE-L space)** | 12.24 | **17.32** | **+5.08 [+3.31, +7.17]** → 차이 확인 |
| dev_debate 200, '토론' 표현 | 1.5% | **19.5%** | 정답 99.5% |

→ **토론 dev에서 점수 개선을 관찰했다.** 전체 dev에서는 차이를 확인하지 못했다(토론이 0.57%라 당연하다).
다만 19.5%는 정답 99.5%와 멀고, 서빙에서 유형을 입력받아야 한다(API 규격 밖). 그래서 **채택은 보류**하고 요구사항이 생기면 Stage C 규모로 다시 학습한다.

### 모델 비교 조건 정정 (2026-09-21)

추가 공정성 한계: 토크나이저와 사전학습 조건이 다르고, T5는 dev 기준 best checkpoint(300스텝), KoGPT2는 마지막 상태(375스텝)를 평가했다. KoGPT2의 기존 실행 코드는 config의 label smoothing 0.1을 전달하지 않아 실제로는 기본값 0.0을 사용했다. 반복 4-gram도 모델별 토큰 단위여서 직접 비교할 수 없다(정답 반복률 T5 6.53%, KoGPT2 0.53%). 따라서 결과는 두 모델과 실행 절차의 비교이며 구조 자체의 인과 효과가 아니다. 2026-09-21 코드 정정으로 smoothing 전달과 프롬프트 잘림 방향을 수정했으나 재학습하지 않았고, 표의 기존 점수는 수정 전 실행 결과다.
