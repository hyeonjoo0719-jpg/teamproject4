## 1. 과제 정의

카카오톡에서 크라우드소싱으로 수집한 SNS 대화 35만 건에 대해 **대화 1건 → 한 문장 요약문 1개**를
생성하는 생성 요약(abstractive summarization) 과제다.
문어 중심으로 개발된 기존 NLP 기술은 생략·축약이 잦은 구어 대화에 잘 맞지 않는다는 문제의식에서 출발했다.

## 2. 데이터 설계 기준 (원본 35만 건 기준)

- 말차례(turn) 최소 4회, 발화(utterance) 최소 8회를 만족하는 대화만 포함
- 대화 유형은 **일상 대화 / 토론 대화** 2종. 둘 다에 해당하면 토론 대화로 분류
- 주제는 **9개 항목**: 개인 및 관계, 주거와 생활, 상거래(쇼핑), 식음료, 여가 생활, 일과 직업, 행사, 미용과 건강, 시사/교육
- 주제 선택 기준은 육하원칙 중 **'무엇을'**에 해당하는 내용
- 반사회적·혐오·차별·선정적 대화는 제외
- Training : Validation : Test = **8 : 1 : 1**, 주제 분포는 층화 표집으로 전체 분포 유지

원문 기준 주제 분포(35만 건): 개인 및 관계 25.40%, 주거와 생활 16.14%, 여가 생활 12.59%,
식음료 10.78%, 상거래(쇼핑) 9.39%, 행사 7.62%, 일과 직업 7.30%, 미용과 건강 6.10%, 시사/교육 4.69%.

참여자 구성은 2인 대화가 93.33%, 화자 성별은 여성 84.27%, 연령대는 20대 78.54%로 **크게 편향**되어 있다.
모델 결과를 일반화할 때 이 편향을 반드시 언급해야 한다.

## 3. 요약문 작성 원칙 (가장 중요)

요약문은 아래 **두 조건 중 하나**를 만족하는 **한 문장**이다.

1. 육하원칙(언제·어디서·누가·무엇을·어떻게·왜) 요소 중 **2가지 이상**을 포함하고, 그중 "누가"를 알 수 있다.
2. (1)을 못 채우면, 대화문에 등장한 **중요 키워드 2개 이상**을 포함한다.

대화 유형별 형식 (테크니컬 리포트 기준)

| 유형 | 형식 |
|---|---|
| 일상 대화 | 육하원칙 기반, "~ 하다/한다" 체 |
| 토론 대화 | "(누가) ~에 대해서 토론한다" |
| 질의응답 대화 | "(A가) ~을 질문하고 (B가) 답변한다" |

> 실제 배포 데이터의 `type` 값은 `일상 대화` / `토론 대화` 두 가지뿐이다. 질의응답 유형은 별도 라벨로 존재하지 않는다.

**요약문에는 비식별화 태그(#@이름# 등)를 포함하지 않는다.** — 실제 데이터에서도 100% 지켜지고 있다(01 문서 참고).
따라서 모델 출력에 `#@...#`이 나오면 그것만으로 규칙 위반이다.

예시(원문 발췌)
- `영등포 CGV에서 영화를 보려고 한다.` (육하원칙 3요소)
- `이번주 일요일에 용산역에서 언니와 동생이 옷을 사려고 만나기로 했다` (6요소)
- `탕수육을 소스에 찍어 먹는 것과 소스를 부어 먹는 것에 대해 토론한다.` (토론 대화)

## 4. 개인정보 비식별화 태그

| 범주 | 태그 | 대상 |
|---|---|---|
| 이름 | `#@이름#` | 실명, 실명 변형, 대화명, 별명, 필명 (일반 애칭·공인 실명은 제외) |
| 온라인 | `#@계정#` | 아이디, 이메일, URL |
| 신원 | `#@신원#` | 주민번호·학번·사번 등 고유 식별 번호 |
| 전화 | `#@전번#` | 전화번호 |
| 금융 | `#@금융#` | 계좌·카드 번호 |
| 번호 | `#@번호#` | 일련번호, 사업자등록번호, 비밀번호 |
| 주소 | `#@주소#` | 동 이하 상세 주소, 아파트·건물명 |
| 소속 | `#@소속#` | 출신·소속 학교/직장/부대 |
| 기타 | `#@기타#` | 위에 없지만 비식별화가 필요한 항목 |

지하철역명·상호명·공인 이름은 비식별화 대상이 **아니다**.
실제 배포 데이터에는 표에 없는 `#@시스템#`, `#@이모티콘#`, `#@URL#` 태그도 존재한다(01 문서 참고).

## 5. 검수 기준 (품질 판단에 그대로 쓴다)

- 다단계 검수: 기계적 검수 → 중복·내용조건 검수 → 수작업 검수 → 교차 검수 → 전문가 검수 → 외부 인증
- 교차 검수는 2인이 독립 수행하고 불일치 시 검수책임자 판단
- 유형 판정: 토론 대화는 **하나의 주제에 두 개 이상의 대립 의견**이 있어야 적합
- 주제 판정: 육하원칙의 '무엇을'에 해당하는 분류가 선택되었는지 확인

우리 프로젝트에서는 사람 교차 검수 대신 **규칙 기반 자동 점검 + Claude 단독 표본 판정 (사람 교차 검수 미실시)**로 대체한다(03 문서).

## 6. 가이드라인이 제안하는 모델링 (2.6.1)

- 화자(speaker)와 발화(utterance)를 이어붙여 시퀀스 인코더에 입력하고, 요약문을 시퀀스 디코더로 예측하는 **seq2seq 구조**
- KoGPT2 토크나이저는 축약 표현·비표준어에서 미등록어(UNK)가 많이 발생 → **SentencePiece 계열 토크나이저** 사용을 권고
- 입력 길이 문제 때문에 dynamic convolution networks 기반 seq2seq를 제안 (2020년 기준)
- 평가는 **ROUGE** 사용

### 가이드라인 시범 모델 성능 (직접 비교 불가능한 참고값)

| 지표 | 점수 |
|---|---:|
| ROUGE-1 | 20.872 |
| ROUGE-2 | 9.156 |
| ROUGE-L | 19.547 |

> 이 수치는 원문에 토큰화 기준이 명시되어 있지 않다. 우리 점수와 직접 비교할 때는
> "토큰화 기준이 다를 수 있음"을 항상 함께 적는다. 절대 비교가 아니라 **참고선**으로만 쓴다.

우리는 가이드라인의 2020년 모델 구조(dynamic convolution)를 그대로 따르지 않고,
같은 **seq2seq + SentencePiece** 원칙을 지키면서 현재 표준인 사전학습 T5 계열을 쓴다.
이 선택의 근거는 `docs/02_pipeline.md` Part 3에 적는다.
