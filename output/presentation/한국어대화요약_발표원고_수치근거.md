# 한국어 대화 요약 발표 원고와 수치 근거

이 문서는 교수님 요구사항을 기준으로 발표 흐름을 구성한 원고다. 메인 결과는 `현중`의 pko-T5 실험을 사용하고, 우리가 실행한 V3 KoBART는 독립 재현 결과로 사용한다. `효창.ipynb`에서는 본 학습 성능이 아니라 데이터 EDA와 효율화 아이디어만 가져왔다.

## 발표 전체 메시지

> 토크나이저, 임베딩, 구조, 전이학습, 하이퍼파라미터와 디코딩을 각각 비교한 뒤 pko-T5 인코더·디코더 구조를 선택했다. 학습 규모를 2천 건에서 28만 건으로 늘리면서 dev ROUGE-L이 22.63에서 27.33으로 상승했고, 공식 Validation 35,004건에서 공백 ROUGE-L 27.15와 형태소 ROUGE-L 45.35를 얻었다. 자동 오류 신호는 개선됐지만 사람 기준의 사실 오류 감소는 아직 확인하지 못했으며, 토론과 긴 대화가 주요 실패 구간이다.

## 슬라이드 3. 데이터 분할과 과제 난이도

### 수치

- Train 278,292건
- Dev 1,500건
- 토론 전용 Dev 200건
- Test: 공식 Validation 전체 35,004건
- train/dev/dev_debate 교차 중복 0건
- 토론 대화 비율 0.574%
- 글자 기준 요약/대화 압축률 0.257
- 신규 unigram 비율: 어절 80.5%, 어간 73.6%

### 해석

대화 표현을 그대로 복사하기보다 문어체로 다시 써야 하는 비중이 높다. 토론 대화가 0.574%뿐이므로 전체 평균은 토론 실패를 거의 반영하지 못한다.

### 주의

신규 unigram 비율은 `효창.ipynb`의 전처리와 사용자 정의 토큰화 기준이다. 외부 벤치마크와 직접 비교하지 않는다.

## 슬라이드 4. 전체 NLP 파이프라인

1. 데이터 분할과 누수 검사
2. 화자·시스템 태그·반복 표현 전처리
3. 문자열을 토큰 ID로 변환
4. ID를 768차원 임베딩으로 변환
5. 인코더가 대화 전체 문맥을 표현
6. 디코더가 이전 생성 토큰과 인코더 출력을 보며 다음 토큰 생성
7. beam·길이·반복 설정으로 디코딩
8. ROUGE, 슬라이스, 오류 사례 평가

입력 상한은 384토큰, 출력 상한은 64토큰이다.

## 슬라이드 5. 토크나이저 선택

| 토크나이저 | vocab | 평균 입력 토큰 | UNK 비율 | UNK 포함 대화 | 정답 복원 |
|---|---:|---:|---:|---:|---:|
| pko-T5 | 50,358 | 147.9 | 0% | 0% | 99.73% |
| ke-T5 | 64,100 | 100.7 | 1.02% | 56.2% | 97.53% |
| mT5 | 250,100 | 129.3 | 0.34% | 30.7% | 99.13% |

### 선택

`paust/pko-t5-base`

### 선택 근거

- 구어체 입력에서 UNK가 발생하지 않았다.
- 정답 문장을 토큰화하고 다시 복원했을 때 99.73%가 동일했다.
- mT5보다 vocab이 작아 임베딩과 VRAM 부담이 작았다.
- 개행을 보존해 화자별 발화 경계를 유지했다.

## 슬라이드 6. 토큰화 오류 사례

ke-T5 왕복 복원 사례:

- `쌩쌩하다` → `하다`
- `얄밉게` → `얄게`
- `깼다` → `다`

토크나이저가 표현을 UNK로 바꾸거나 잃어버리면 파인튜닝 이후에도 원래 표현을 생성하기 어렵다. 토큰 수가 짧다는 이유만으로 토크나이저를 선택하지 않았다.

## 슬라이드 7. 임베딩

### pko-T5

- vocab 50,358
- d_model 768
- 임베딩 파라미터 50,358×768 = 38.7M
- 전체 275.6M 파라미터의 14.0%

### mT5

- vocab 250,100
- 같은 768차원으로 계산하면 임베딩 약 192.1M
- pko-T5 전체 모델의 약 70%에 해당

### 해석

8GB VRAM에서는 큰 vocab이 학습 가능한 배치를 줄인다. mT5는 복원률이 높았지만 계산 비용 때문에 제외했다.

## 슬라이드 8. 구조 선택

### 인코더·디코더 pko-T5

- 인코더 12층, hidden 768, head 12, FFN 2048
- 디코더 12층과 cross-attention
- 전체 파라미터 275.6M

### 디코더 전용 KoGPT2

- 대화와 요약을 한 시퀀스로 연결
- 요약 부분에만 loss 적용
- 생성 시 프롬프트 이후 토큰만 분리

### 제한 조건 비교

| 구조 | 모델 | ROUGE-L | 반복 4-gram | 학습 시간 | VRAM |
|---|---|---:|---:|---:|---:|
| 인코더·디코더 | pko-T5 | 22.63 | 8.2% | 12.5분 | 7.15GB |
| 디코더 전용 | KoGPT2 | 14.71 | 23.6% | 2.0분 | 4.42GB |

### 선택과 한계

pko-T5를 선택했다. 다만 모델 크기, 토크나이저, 체크포인트 선택, label smoothing 조건이 다르므로 7.9점 차이를 구조의 순수 효과라고 말하지 않는다.

## 슬라이드 9. 전이학습

같은 구조, 토크나이저, 2,000건, 주요 학습 설정에서 초기화만 바꿨다.

| 초기화 | train loss | dev ROUGE-L | 생성 예시 |
|---|---:|---:|---|
| 사전학습 pko-T5 | 2.8973 | 22.63 | 정상적인 한국어 요약 |
| 무작위 초기화 | 44.23 | 5.93 | `아니야 안 것 한다.` |

### 해석

2,000건만으로 한국어 자체를 새로 학습하기는 어렵다. 파인튜닝에서는 이미 배운 한국어 표현 능력을 유지하면서 요약 방식을 학습한다.

## 슬라이드 10. 파인튜닝 설정

| 항목 | 선택 | 근거 |
|---|---|---|
| 입력/출력 길이 | 384/64 | 커버리지 99.44%/99.93% |
| micro batch×누적 | 4×4 | 유효 배치 16 |
| 학습률 | 1e-4 | 5e-5보다 0.93점 높음 |
| 정밀도 | bf16 | 8GB VRAM, 직접 비교하지 않은 관행 기반 결정 |
| epoch | 2 | 3 epoch와 차이 미확인 |
| label smoothing | 0.1 | 0.0은 반복 증가, 점수 차이 미확인 |
| warmup | 5% | 0%·10%와 차이 미확인 |
| weight decay | 0.01 | 비교하지 못함 |

## 슬라이드 11. 학습 규모별 변화

| 단계 | 학습 건수 | 스텝 | 시간 | dev ROUGE-L | 이전 단계와 차이 |
|---|---:|---:|---:|---:|---|
| A | 2,000 | 375 | 12.5분 | 22.63 | 기준 |
| B | 20,000 | 2,500 | 38분 | 25.16 | +2.53 [+1.80,+3.23] |
| C | 278,292 | 34,788 | 371분 | 27.33 | +2.17 [+1.36,+2.87] |

A→B에서는 데이터와 epoch가 함께 바뀌었으므로 데이터 양의 단독 효과로 확정하지 않는다.

## 슬라이드 12. 하이퍼파라미터 비교

| 변경 | 기준 대비 차이 | 판정 |
|---|---|---|
| 학습률 5e-5 | −0.93 [−1.44,−0.41] | 더 낮음 |
| 유효 배치 32 | −0.87 [−1.40,−0.40] | 더 낮음 |
| length penalty 0.8 | −0.44 [−0.71,−0.17] | 더 낮음 |
| 학습률 3e-4 | −0.31 [−0.96,+0.37] | 차이 미확인 |
| epoch 3 | −0.06 [−0.57,+0.45] | 차이 미확인 |

학습률 3e-4는 train loss가 가장 낮았지만 ROUGE가 높지 않았다. loss 개선과 생성 품질 개선은 같은 의미가 아니다.

## 슬라이드 13. 디코딩 전략

| 전략 | ROUGE-L | 1,500건 생성 시간 | 판정 |
|---|---:|---:|---|
| greedy, beam 1 | 25.86 | 131초 | beam 4보다 −1.60 |
| beam 2 | 26.94 | 167초 | beam 4보다 −0.516 |
| beam 4 | 27.46 | 180초 | 선택 |
| length penalty 1.2 | 27.45 | 180초 | 차이 미확인 |
| length penalty 0.8 | 27.02 | 180초 | −0.44, 더 낮음 |

`no_repeat_ngram_size=3`은 정답 요약의 13.37%에 실제로 존재하는 반복까지 막았다. 최종값은 0으로 설정했다.

## 슬라이드 14. 최종 평가와 지표 해석

| 평가셋 | n | 공백 ROUGE-L | 형태소 ROUGE-L | 자동 점검 통과율 |
|---|---:|---|---|---:|
| Dev | 1,500 | 27.46 [26.47,28.42] | 45.29 [44.44,46.10] | 97.3% |
| Test | 35,004 | 27.15 [26.95,27.36] | 45.35 [45.16,45.54] | 97.0% |

### 지표 해석

- 공백 기준은 조사·어미가 붙은 표현을 다른 단어로 본다.
- 형태소 기준은 공통 형태소를 더 많이 포착한다.
- ROUGE는 표현의 겹침이며 사실성 점수가 아니다.
- 자동 점검 97%도 사실 정확도 97%라는 뜻이 아니다.
- 비교할 때 토큰화 기준, 평가 건수, 디코딩을 함께 표기한다.

## 슬라이드 15. 독립 KoBART 실행

### 실제 실행

- 전체 378.3분
- 학습 345.0분
- Train 265,000건
- 공식 Validation 35,004건 전체

| 방법 | Validation 어절 RL | Validation 글자 RL | 내부 Test 어절 RL | 내부 Test 글자 RL |

## 슬라이드 18. 같은 대화에서 단계별 요약 변화

정답: `아이패드와 애플 펜슬도 써봤는데 그냥 연필 쓰는 느낌이다.`

- Stage A: `펜슬도 써봤고 캐치마인드 할 때 편할 것 같다.`
  - 아이패드 핵심 누락
- Stage B: `아이패드에 낙서를 해봤는데 연필 쓰는 느낌이라 캐치마인드 할 때 편할 것 같다.`
  - 핵심 포함
- Stage C: `아이패드 펜슬은 연필 쓰는 느낌이라 캐치마인드할 때 편할 것 같다.`
  - 더 간결

남은 사실 오류 예: 에어컨 때문에 추운 원인을 `날씨가 추워져서 에어컨이 세다`로 뒤집었다. 원인·수식 대상을 연결하는 과정에서 오류가 발생한 사례다.

## 슬라이드 21. 결론과 한계

### 확인한 것

- pko-T5 토크나이저는 UNK 0%, 정답 복원 99.73%
- 전이학습은 무작위 초기화보다 +16.71점
- Stage A→B→C에서 22.63→25.16→27.33
- beam 4는 greedy보다 +1.60점

## 교수님 질문 대비

### 왜 pko-T5인가

UNK가 없고 정답 복원률이 99.73%였으며, 제한된 모델 비교에서 KoGPT2보다 ROUGE-L이 7.9점 높았다. mT5는 임베딩만 약 1.92억 파라미터라 8GB VRAM 제약에 불리했다.

### 왜 인코더·디코더인가

요약은 입력 전체를 읽은 뒤 짧게 다시 쓰는 과제다. 인코더가 전체 입력을 양방향으로 표현하고 디코더가 cross-attention으로 이를 참조한다. 제한 비교 결과도 pko-T5가 높았지만 구조 이외 조건이 달라 인과 효과로 확정하지 않는다.

### 왜 공백과 형태소 ROUGE가 크게 다른가

한국어는 조사와 어미가 단어에 붙는다. 공백 기준에서는 `영화를`과 `영화가`가 완전히 다르지만 형태소 기준에서는 `영화`가 공통으로 잡힌다.

### 자동 점검 통과율이 정답보다 높은 이유

자동 점검은 키워드, 길이, 한 문장, 반복 등을 확인하는 근사 규칙이다. 실제 품질이나 사실성을 측정하지 않는다. 따라서 정답보다 수치가 높아도 모델이 정답보다 좋다는 뜻이 아니다.

### 오류가 실제로 줄었다고 말할 수 있는가

ROUGE 0점 비율과 내용어 포함률 같은 자동 신호는 개선됐다. 그러나 30건 AI 판정에서는 오류가 단조롭게 줄지 않았고 사람 검증도 없다. 실제 오류 감소는 아직 한계로 남긴다.

### 토론 문제를 왜 완전히 해결하지 않았는가

유형 표시로 토론 dev가 5.08점 개선됐지만 서비스 입력에는 유형이 없으며, `토론` 표현률도 정답 99.5%에 비해 19.5%에 그쳤다. 새로운 holdout 검증도 필요하다.
