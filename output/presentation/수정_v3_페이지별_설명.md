# 발표자료 v3 변경 안내와 발표 흐름

기존 2·7·20페이지는 삭제했습니다. 기존 10·12페이지는 하나의 설정 선택 페이지로 합쳤습니다. 개념 설명을 먼저 배치하고, 성능 평가에서 오류 분석으로 이어지도록 순서를 바꿨습니다. 마지막 결론은 요청대로 내용 수정을 보류했습니다.

## 오류 사례를 발표할 때

“날짜가 22일에서 25일로 바뀌었다”는 원문과 출력으로 확인한 관찰입니다. “토크나이저 때문에 그랬다”는 현재 증명하지 못했습니다. 따라서 원인을 확정하는 대신 날짜 정규화·원문 숫자 대조, 질문과 응답의 연결 보강, 추측 표현 보존 학습을 검증할 방법으로 제시했습니다. 같은 사례에서 개선 전후를 비교해야 해결 효과를 말할 수 있습니다.

## 팀원 결과를 받으면 할 일

1. 두 리뷰어가 같은 40건을 판정했는지 확인합니다.
2. 공통 판정 건수와 일치율·Cohen’s κ를 확인합니다. 보류 제외 여부도 함께 적습니다.
3. 불일치 사례는 원문의 근거를 비교하고 합의 또는 보류로 남깁니다.
4. 합의된 오류 유형별 건수와 대표 사례를 19페이지에 넣습니다. 복수 유형을 허용했다면 합계가 사례 수를 넘을 수 있음을 표시합니다.
5. 위험 후보로 선택한 40건의 결과를 전체 데이터의 환각률로 확대하지 않습니다.
6. 단계별 오류 감소를 주장하려면 동일 대화의 A·B·C 출력에 대한 별도 짝지은 재판정이 필요합니다. 현재 KoBART 40건만으로는 입증할 수 없습니다.
7. 마지막 결론의 ‘사람 100건 재평가’와 현재 40건 작업의 관계, 후속 실험 범위, 반올림 차이(+16.71 대 약 +16.70)를 최종 결과에 맞게 정리합니다. 이번 파일에서는 요청대로 결론 내용을 보존했습니다.

## 근거 및 검수

실험 수치는 현중/docs/07_full_report.md, 03_evaluation.md, 04_experiment_log.md와 관련 노트북을 확인했습니다. 압축률은 효창.ipynb, 원문 예시는 output/data_understanding/sample_pairs.json과 실제 test_predictions.csv에서 확인했습니다. 각 슬라이드 발표자 노트에 출처와 해석상 주의를 적었습니다.

발표자료는 기존 디자인·서체를 유지했고, 표와 그래프는 편집 가능한 PowerPoint 객체로 구성했습니다. 파일 구조·차트 데이터·레이아웃 자동 검사와 렌더링 화면 검수를 수행했습니다. 실제 PowerPoint 앱에서의 실행 검증과 새 모델 학습은 수행하지 않았습니다.
