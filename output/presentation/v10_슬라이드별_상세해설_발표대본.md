# 한국어 대화 요약 발표 v10: 상세 해설과 발표 대본

기준: `한국어대화요약_발표자료_수정_v10.pptx`의 실제 23페이지. PPT 원본은 변경하지 않음. 설명은 발표자 학습용, 인용문은 말로 읽는 대본. 페이지당 약 30~50초를 목표로 한 초안이며 실제 시간은 리허설로 확인 필요.

## 먼저 알아둘 발표의 범위

핵심 흐름: 데이터 이해 → 표현 보존 → 모델 구조·전이학습 → 설정 선택 → 최종 성능 → 취약 구간 → 사실 오류 분석과 한계.

1. **최종 선택 모델은 pko-T5, 뒤쪽 40건의 오류 분석 대상은 KoBART.** 18~22페이지에서 모델 이름을 생략해도 평가 대상이 바뀌는 것은 아님. 두 모델의 성능 수치를 하나로 합쳐 설명하지 않기.
2. **20페이지의 통합 재검토 열은 AI의 원문 대조 결과.** A/B는 사람의 독립 판정이지만 7·25·0·1·7이라는 재검토 분포는 AI가 작성. 현재 ‘팀원 검토 기준 사실 오류’라는 문구는 출처와 불일치하므로 발표에서는 ‘AI 보조 재검토 기준’으로 설명 필요. 실제 팀원 최종 확인 전에는 인간 합의 완료라고 말하지 않기.
3. **ROUGE 점수 상승과 사실 오류 감소는 다른 성과.** 97.0%는 자동 규칙 통과율, 99.73%는 문자열 복원률. 모두 사실 정확도와 구분.
4. **확인한 것은 오류 양상과 개선 방향.** 제안한 처리로 환각이 감소했다는 개선 실험 결과는 아직 없음. 1페이지의 ‘오류 수정까지’도 모델의 오류 감소 실증을 뜻하는 것으로 설명하지 않기.
5. **수치 정합성:** 9페이지의 22.63−5.93은 표시값 기준 +16.70점. 23페이지 +16.71점과 미세하게 다름. 대본에서는 ‘약 16.7점’으로 통일. 27.33과 27.46은 평가 실행 경로가 다른 기록이며 단순 반올림 차이가 아님.

## 1페이지. 한국어 대화 요약 모델

### 핵심 메시지

구어체 대화를 한 문장으로 요약하는 모델을 만들고, 각 선택을 실험과 오류 사례로 검토한 프로젝트.

### 용어·내용 설명

- **대화 요약:** 여러 발화에서 중심 사건·결정·의견을 골라 짧게 표현하는 작업. 단순 글자 수 축소와 다름.
- **생성형 요약:** 원문 문장을 그대로 고르기만 하는 추출형과 달리 새로운 문장을 생성. 자연스러운 표현이 가능하지만 원문에 없는 사실을 만들 위험도 존재.
- **pko-T5:** 최종 선택한 한국어 사전학습 모델. 대화를 읽는 인코더와 요약을 생성하는 디코더로 구성.
- **공식 Validation 35,004건:** 원 데이터의 이름은 Validation이지만 이 프로젝트에서는 최종 평가용으로 사용. 학습 도중 설정을 고르는 Dev 1,500건과 별개.

### 알아둘 점

‘모든 선택을 완전히 검증’하거나 ‘환각 해결 완료’한 프로젝트로 소개하지 않기. 토큰화, 모델·설정 선택, 출력 오류의 관찰은 했지만 내부 원인과 수정 효과는 일부 미검증.

### 간단 대본

> 저희는 한국어 채팅 대화를 한 문장으로 요약하는 모델을 만들었습니다. 최종 선택 모델은 pko-T5이며, 토큰화부터 학습 설정과 생성 방식까지 선택 근거를 비교했습니다. 마지막으로 평균 점수만으로 드러나지 않는 오류 사례와 추가 검증이 필요한 부분을 설명하겠습니다.

## 2페이지. 데이터 예시: 채팅을 읽고 문장으로 요약

### 핵심 메시지

입력은 생략·웃음·불완전한 문장이 섞인 채팅, 학습 목표는 중심 관계를 보존한 서술형 요약.

### 용어·내용 설명

- **P01·P02:** 대화 내부에서 참여자를 구분하는 화자 ID. 실제 사람의 이름이나 전체 데이터 공통 인물 ID라는 뜻은 아님.
- **발화:** 한 참여자가 말한 하나의 메시지 단위. 여러 발화가 모여 대화 한 건 구성.
- **구어체:** 실제 대화에 가까운 표현. ‘배송비드니’, ‘히히’, ‘머?’ 같은 생략·반응 포함.
- **문어체·서술형:** 띄어쓰기와 문장 구조를 정리해 독립적으로 읽을 수 있는 표현. 원문의 모든 말을 그대로 나열하지 않음.
- **정답 요약:** 데이터에 제공된 reference. 여기서는 ‘함께 구매하면 무료 배송’이라는 조건과 같이 사자는 제안을 보존.

### 알아둘 점

화자 P01의 ‘나혼자살게’도 있으므로 ‘결국 같이 구매하기로 합의’라고 말하면 과장. 정답은 같이 사자고 제안했다는 내용이지 합의 완료가 아님. 정답 요약도 절대적인 사실 판정 기준은 아니며 원문 확인 필요.

### 간단 대본

> 실제 입력에는 띄어쓰기가 없거나 짧은 반응이 이어지는 표현이 많습니다. 정답 요약은 이런 표현을 정리하면서, 함께 사면 배송비가 없다는 핵심 관계를 남깁니다. 따라서 저희 과제는 단순히 문장을 줄이는 것이 아니라, 누가 어떤 제안을 했는지 유지하면서 읽기 좋은 문장으로 만드는 것입니다.

## 3페이지. 학습용·검증용·최종 평가용 데이터

### 핵심 메시지

학습에 쓰는 데이터, 설정 선택에 쓰는 데이터, 마지막 성능 확인용 데이터를 구분.

### 용어·수치 설명

- **Train 278,292건:** 정답을 이용해 가중치를 갱신하는 데이터.
- **Dev 1,500건:** development set. 학습률, 체크포인트, 디코딩 등의 선택 기준. 직접 학습하지 않아도 여러 번 선택에 사용하면 이 데이터에 간접적으로 맞춰질 수 있음.
- **토론 전용 Dev 200건:** 일반 Dev에는 토론이 8건뿐이므로 별도 취약 유형 점검용으로 확보.
- 공식 Train 279,992건에서 `278,292 + 1,500 + 200`으로 분할. 공식 Validation 35,004건은 별도 최종 평가용.
- **토론 대화:** 특정 주제를 두고 의견을 주고받는 데이터 유형 라벨. 말다툼 여부를 임의 판정한 기준이 아님.
- **길이 비율 0.257:** 각 대화에서 `요약 글자 수 / 대화 글자 수`를 구하고 평균한 값. 전체 글자 수를 모두 합쳐 나눈 비율과 반드시 같지 않음.

### 알아둘 점

25.7%는 길이이지 ‘정보 25.7%만 보존’이 아님. 글자 수 감소율 74.3%를 정보 손실률로 설명하지 않기. 토론 비율 0.574%는 공식 Train 기준이고, 최종 평가의 토론 188/35,004건과 분모가 다름. 최종 평가를 본 뒤 탐색한 개선안은 새로운 미사용 평가셋이 필요.

### 간단 대본

> 데이터는 학습용 약 27만 8천 건, 설정 선택용 1,500건, 최종 평가용 35,004건으로 구분했습니다. 일반 검증셋에는 토론이 8건뿐이어서 토론 전용 200건도 따로 확보했습니다. 요약 길이는 평균적으로 대화의 약 25.7%이지만, 이는 길이 압축 정도이지 정보 보존율은 아닙니다.

## 4페이지. 대화가 요약문이 되는 과정

### 핵심 메시지

문자열을 숫자 표현으로 바꾸고, 문맥을 계산해 요약 토큰을 생성한 뒤 평가하는 전체 과정.

### 용어·내용 설명

1. **입력 정리:** 화자 구분을 유지하면서 시스템 태그 등 텍스트 내용과 무관한 표시를 처리.
2. **토큰화:** 문자열을 모델의 어휘 단위로 나누고 정수 ID 부여. 한글 한 글자와 토큰 한 개는 다를 수 있음.
3. **임베딩:** 토큰 ID로 학습된 벡터를 조회. 이 모델의 차원은 768. ‘단어의 뜻 768개’나 ‘768개 토큰’이라는 뜻은 아님.
4. **인코더:** 앞뒤 토큰의 관계를 반영한 문맥 표현 계산.
5. **디코더:** 원문 표현과 이미 만들어진 요약을 참고해 다음 토큰의 확률 계산.
6. **생성 전략:** 그 확률에서 어떤 토큰 후보를 유지할지 결정.
7. **문자열 복원:** 생성한 ID들을 사람이 읽는 문자열로 decode. 신경망 디코더와 이름은 비슷하지만 다른 기능.

**384/64:** 입력 최대 384토큰, 출력 최대 64토큰이라는 이번 실행 설정. 모델의 보편적·절대적 처리 한계가 아님. 길이가 짧은 입력을 억지로 의미 있는 384토큰으로 늘리는 것이 아니라 배치 처리용 padding을 쓸 수 있고, padding은 attention mask로 구분. 출력은 EOS라는 종료 토큰이 나오면 더 일찍 끝날 수 있음.

### 알아둘 점

입력 잘림으로 지워진 내용은 모델이 직접 볼 수 없음. 긴 대화 문제의 가능한 원인이지만, 모든 긴 대화 오류가 잘림 때문이라고 단정하지 않기.

### 간단 대본

> 먼저 입력을 정리하고 문장을 토큰 번호로 바꿉니다. 임베딩은 이 번호를 768차원 벡터로 표현하고, 인코더는 대화의 문맥을 계산합니다. 디코더는 그 정보를 참고해 요약을 한 토큰씩 만듭니다. 입력 384와 출력 64는 이번 실험에서 정한 길이 상한이며, 넘는 입력은 잘릴 수 있고 출력은 종료 표시가 나오면 더 일찍 끝납니다.

## 5페이지. 토크나이저 선택: 표현 보존 정도

### 핵심 메시지

의미 이해에 앞서, 입력 표현을 알 수 없는 기호로 바꾸거나 잃어버리지 않는지 점검.

### 용어·수치 설명

- **UNK:** unknown token. 토크나이저가 표현하지 못한 부분을 나타내는 특수 토큰.
- **UNK 포함 대화 비율:** 한 대화에 UNK가 하나라도 있으면 포함 사례로 계산. ke-T5의 56.2%는 전체 토큰의 56.2%를 잃었다는 뜻이 아님.
- 검증 1,500건에서 pko-T5 0%, ke-T5 56.2%, mT5 30.7%.
- **BBPE:** 바이트를 기본 단위로 삼는 BPE 방식. pko-T5는 BBPE를 사용하므로 드문 표현도 바이트 조합으로 표현할 수 있어 UNK 0%가 이상한 결과는 아님. 개발사 설명도 OOV 없는 BBPE 사용을 명시. [모델 카드](https://huggingface.co/paust/pko-t5-base)
- **문자열 복원률:** 정답 문자열을 encode하고 decode한 결과가 같은 표현으로 복원됐는지 확인. pko-T5 99.73%, ke-T5 97.53%, mT5 99.13%.

### 알아둘 점

UNK가 적어도 토큰 수가 늘어 계산 비용이 커질 수 있음. UNK 0%는 모든 문장을 이해한다는 뜻이 아님. 또한 토크나이저만 서로 바꾸어 기존 모델에 끼우면 ID와 임베딩의 대응이 깨질 수 있으므로 모델·토크나이저 쌍으로 이해. 이번 비교는 해당 모델 계열의 표현 보존 비교이지 토크나이저 교체만의 요약 성능 실험이 아님.

### 간단 대본

> 먼저 표현 자체가 사라지는지 확인했습니다. pko-T5는 검증 대화에서 UNK가 포함된 사례가 없었고 정답 문자열 복원률은 99.73%였습니다. 다만 바이트 기반 토큰화의 특성도 작용하므로, 이 수치를 구어체 이해 능력으로 해석하지 않았습니다. 표현 보존은 유리했지만 실제 요약 품질과 계산 비용은 별도로 비교했습니다.

## 6페이지. “왕복 복원”은 숫자로 바꿨다가 되돌리는 검사

### 핵심 메시지

요약을 생성하기 전, 문자열 변환 과정에서 표현이 손실되는지 검사.

### 용어·내용 설명

- **encode:** 원문 문자열에서 토큰 ID 배열로 변환.
- **decode:** 그 ID 배열을 다시 문자열로 변환.
- **왕복:** `문자열 → ID → 문자열`. 모델이 원문을 요약했다가 다시 원문으로 늘린다는 뜻이 아님.
- ‘쌩쌩하다→하다’, ‘얄밉게→얄게’, ‘깼다→다’는 변환 후 표현 일부가 사라진 사례. 행동·상태를 나타내는 부분이 사라지면 후속 모델이 사용할 단서도 줄어들 수 있음.
- **정규화:** 모양이 비슷한 유니코드 문자를 일관된 방식으로 맞추는 처리. 복원 실패에는 정규화·공백 차이가 포함될 수 있으므로, 모든 불일치를 의미 손실로 단정하지 않음.

### 알아둘 점

99.73%는 새 요약을 정답처럼 만든 확률이 아님. 세 예시는 ke-T5의 관찰 사례이지 모든 입력에서 이런 손실이 생긴다는 뜻은 아님.

### 간단 대본

> 왕복 복원은 문장을 숫자로 바꿨다가 같은 숫자를 다시 문자로 되돌리는 검사입니다. 예를 들어 일부 토크나이저에서는 ‘깼다’가 ‘다’로 돌아와 중요한 표현이 사라졌습니다. 이 단계는 새로운 요약을 만드는 실험이 아니라, 모델에 들어가기 전 표현을 얼마나 보존하는지 확인하는 검사입니다.

## 7페이지. 인코더·디코더와 디코더 전용의 차이

### 핵심 메시지

대화와 요약을 분리해 처리하는 구조와, 한 시퀀스에서 대화 뒤에 요약을 이어 쓰는 구조의 비교.

### 용어·내용 설명

- **Transformer:** 토큰 간 관련성을 계산하는 attention과 각 위치의 변환을 반복해 문맥을 학습하는 신경망.
- **Self-attention:** 같은 시퀀스 안에서 다른 토큰의 정보를 참고하는 연산. ‘응’이 어떤 질문에 대한 답인지 연결하는 문제를 생각하면 이해하기 쉬움. 실제로 정확히 연결했는지는 별도 검증.
- **인코더 12층:** 입력의 앞뒤 문맥을 함께 참고하는 계산을 여러 층 수행.
- **디코더 12층:** 이미 생성한 요약 토큰만 앞부분으로 보고 다음 토큰을 예측. 아직 생성하지 않은 정답 뒷부분을 보고 생성하면 안 되므로 causal mask 사용.
- **교차 어텐션:** 디코더의 상태로 인코더가 계산한 원문 정보를 참고.
- **디코더 전용:** 원문과 ‘요약:’ 등을 앞에 두고 다음 부분으로 요약을 생성. 별도의 인코더가 없을 뿐 입력을 이해하지 못한다는 뜻은 아님.
- **Teacher forcing:** 학습 시 이전 정답 토큰을 주고 다음 정답 토큰을 맞추도록 학습. 실제 생성에서는 자신이 만든 이전 토큰을 사용하므로 오류가 뒤에 영향을 줄 수 있음.

T5는 다양한 언어 과제를 텍스트 입력·텍스트 출력으로 통일한 모델 계열. [T5 원 논문](https://www.jmlr.org/papers/v21/20-074.html)

### 알아둘 점

층 수는 연속된 24문장 처리나 24회 요약이라는 뜻이 아님. attention은 관련성 계산 방식이며 인간 수준의 이해 또는 사실 검증 장치와 동일하지 않음.

### 간단 대본

> pko-T5는 대화를 읽는 인코더와 요약을 쓰는 디코더가 분리된 구조입니다. 디코더는 교차 어텐션을 통해 원문 정보를 참고합니다. 반면 KoGPT2는 대화 뒤에 요약을 이어 쓰는 디코더 전용 구조입니다. 두 방식 모두 다음 토큰을 예측하지만, 원문 정보를 처리하고 참조하는 방식이 다릅니다.

## 8페이지. 모델 비교에서 pko-T5를 선택한 근거

### 핵심 메시지

이번 비교 조건에서는 pko-T5가 더 높은 점수, KoGPT2가 더 적은 시간·메모리 사용.

### 용어·수치 설명

- **ROUGE-L:** reference와 생성 요약의 최장 공통 부분수열을 이용한 겹침 지표. 단어가 반드시 연속할 필요는 없지만 순서는 유지. [ROUGE 원 논문](https://aclanthology.org/W04-1013/)
- **Precision:** 생성한 표현 중 정답과 겹친 부분의 비중. **Recall:** 정답 표현 중 생성문이 담은 부분의 비중. **F1:** 두 값을 함께 반영하는 조화평균. 이 프로젝트에서는 0~100점으로 보고.
- pko-T5 22.63, KoGPT2 14.71, 표시값 차이 **7.92점**.
- 학습 2,000건, Dev 1,500건, 유효 배치 16, epoch 3, beam 4를 공통으로 설정.
- 시간 12.5분 대 2.0분으로 약 6.25배, 메모리 7.15GB 대 4.42GB로 약 1.62배. 이 실행 조건의 관측값이며 모든 환경의 배율은 아님.

### 알아둘 점

크기·토크나이저·사전학습·학습률·체크포인트 선택 차이가 있어 ‘인코더가 있어서 7.92점 상승’이라고 인과 해석 불가. 기록상 pko-T5는 best, KoGPT2는 마지막 상태를 평가했고 KoGPT2 실행의 label smoothing도 다름. 이후 코드 정정은 있었으나 해당 비교 수치는 정정 전 실행 결과. 발표의 선택 근거는 ‘제한된 예산에서 시험한 모델·실행 구성 중 점수 우세’.

### 간단 대본

> 같은 데이터 규모와 주요 조건에서 pko-T5는 22.63점, KoGPT2는 14.71점이었습니다. pko-T5가 약 7.92점 높아 성능을 우선해 선택했습니다. 대신 학습 시간과 메모리 사용량은 더 컸습니다. 모델 크기와 사전학습 등도 다르기 때문에, 이 결과를 구조 하나의 효과로 해석하지는 않았습니다.

## 9페이지. 전이학습: 한국어 사전학습 모델을 대화 요약에 적용

### 핵심 메시지

언어를 처음부터 학습하지 않고, 기존 언어 표현을 요약 과제에 맞게 조정.

### 용어·수치 설명

- **가중치·파라미터:** 학습으로 바뀌는 모델 내부 숫자.
- **사전학습:** 대규모 텍스트로 언어 표현을 먼저 학습. pko-T5의 공개 설명은 텍스트 일부 구간을 가리고 복원하는 span corruption 기반 학습을 명시. 이미 모든 대화 요약을 학습한 모델이라는 뜻은 아님. [pko-T5 모델 카드](https://huggingface.co/paust/pko-t5-base)
- **전이학습:** 그 가중치를 다른 과제에 활용하는 큰 개념.
- **파인튜닝:** 이번 대화·정답 쌍으로 가중치를 추가 갱신하는 방식. 모델에게 예시를 프롬프트로 보여주기만 하는 것과 다름.
- **무작위 초기화:** 같은 구조의 숫자를 학습되지 않은 상태에서 시작하는 기준선.
- 2,000건 조건에서 5.93 대 22.63, 약 **16.7점 차이**.

### 알아둘 점

처음부터 학습한 모델에 충분한 데이터와 시간을 줘도 항상 같은 차이가 난다고 말할 수 없음. 비교는 제한된 학습 예산에서 사전학습의 실용적 이점을 보여줌.

### 간단 대본

> 전이학습은 이미 학습한 언어 지식을 새 과제에 활용하는 방식입니다. 저희는 한국어 사전학습 가중치를 불러와 대화와 정답 요약으로 추가 학습했습니다. 같은 2,000건 조건에서 무작위 초기화는 5.93점, 사전학습 사용은 22.63점으로 약 16.7점 차이가 났습니다. 이후 실험도 사전학습 가중치를 사용했습니다.

## 10페이지. 설정 간 점수 차이의 신뢰성 확인

### 핵심 메시지

평균 점수 차이뿐 아니라, 평가 사례 구성에 따라 그 차이가 얼마나 흔들리는지도 확인.

### 용어·수치 설명

- **Paired:** 같은 대화에 대한 설정 A와 B의 점수를 한 쌍으로 유지. 서로 다른 난이도의 대화를 비교하는 문제 방지.
- **Bootstrap:** 이미 있는 평가 사례에서 중복을 허용해 다시 뽑고 평균 차이를 계산하는 재표집.
- 여기서는 Dev 쌍을 원래 표본 크기만큼 뽑는 과정을 1,000회 반복. ‘대화 1,000건만 평가’ 또는 ‘모델을 1,000번 학습’과 다름.
- **95% 구간:** 재표집 차이 분포의 2.5~97.5백분위. 반복 표본 추출에서 추정의 불확실성을 나타내는 근사 신뢰구간.
- 학습률 0.00005: 기준 0.0001 대비 −1.44~−0.41점. 전체 구간이 음수여서 기준보다 낮다는 근거.
- 0.0003: −0.96~+0.37점. 0을 포함하므로 이 분석으로 차이를 확인하지 못함.

### 알아둘 점

0 포함은 두 설정이 완전히 같다는 증거가 아님. 이 구간은 평가 표본 변동을 반영하며, 다른 seed로 재학습했을 때의 변동·반복적인 Dev 탐색 편향·평가자 오류를 포괄하지 않음. ‘95%의 문장이 이 범위 점수’도 틀린 해석.

### 간단 대본

> 작은 점수 차이가 평가 사례에 따라 달라질 수 있어 paired bootstrap을 사용했습니다. 같은 대화의 두 결과를 묶어 1,000번 재표집하고 평균 차이의 구간을 구했습니다. 학습률을 낮춘 경우 구간 전체가 0보다 작아 성능 저하 근거가 있었지만, 높인 경우는 0을 포함해 차이를 확인하지 못했습니다.

## 11페이지. 파인튜닝 설정과 실제 선택 근거

### 핵심 메시지

데이터 길이, 메모리 제한, 비교 성능을 함께 고려해 학습 설정 선택.

### 용어·수치 설명

- **384 선정:** 정규화 전 화자 표시 입력 길이의 99.44%를 포함. 256은 약 94.43%, 512는 99.93%. 512의 추가 커버리지는 약 0.49%p지만 더 긴 시퀀스는 연산·메모리 부담 증가. 모든 길이를 재학습해 최적값을 찾은 결과가 아니라 길이 분포와 자원 기준 선택.
- **64 선정:** 정답 길이의 99.93% 포함. 정답 길이 99.9백분위가 63토큰이라는 기록.
- 최종 speaker/drop 전처리 후에는 384 이내 입력 비율 99.66%. 슬라이드 99.44%는 선정 당시 정규화 전 측정값.
- **microbatch 4:** GPU에서 한 번에 처리하는 대화 4건.
- **gradient accumulation 4:** 네 번 계산한 기울기를 모아 한 번 갱신. 단일 GPU 기준 유효 배치 `4×4=16`.
- **학습률 0.0001:** 갱신의 크기를 조절하는 계수. 모든 가중치에 똑같이 0.0001을 더한다는 뜻은 아님.
- **epoch 2:** 전체 Train을 두 번 순회하는 설정. **step:** 일반적으로 optimizer가 가중치를 한 번 갱신하는 단위.

### 알아둘 점

8건 8.54GB는 최대 길이를 채운 더미 배치 메모리 점검. 실제 학습 최대 7.15GB와 같은 측정 조건이 아님. 3 epoch 설정은 기록상 조기 종료됐으므로 ‘완전한 3회 학습 결과’라고 설명하지 않기. 배치16과32 비교에서 더 큰 배치가 언제나 나쁘다는 결론도 불가.

### 간단 대본

> 입력 길이 384는 대화 대부분을 보존하면서 메모리를 고려해 정했습니다. 입력의 99.44%, 정답은 출력 상한 64에서 99.93%가 잘리지 않았습니다. 한 번에 8건을 올리면 메모리를 초과해 4건씩 네 번 누적했습니다. 학습률은 0.0001을 유지했고, 배치나 학습 횟수를 늘리는 변경에서는 이득을 확인하지 못했습니다.

## 12페이지. 작은 실험을 통과한 뒤 전체 데이터로 확대

### 핵심 메시지

비싼 전체 학습 전에 코드 동작과 설정을 작은 실험에서 점검.

### 용어·수치 설명

- **64건 재현 점검:** 아주 작은 학습 데이터를 모델이 외우다시피 재현할 수 있는지 검사. 실패하면 데이터·손실·생성 파이프라인의 오류를 의심할 수 있음.
- **일반화:** 학습에 직접 쓰지 않은 입력에서도 잘 요약하는 능력. 학습 문장을 잘 외운 것과 별개.
- Stage A: 2,000건, 12.5분, 22.63점. 입력 형식 비교.
- Stage B: 20,000건, 38분, 25.16점. 학습률·배치 등 비교.
- Stage C: 278,292건, 371분, 27.33점. 선택 설정의 전체 학습.
- **371분:** 2 epoch 설정의 전체 학습 실행 시간. epoch 한 번마다 371분이라는 뜻은 아님.

### 알아둘 점

A에서 B로 갈 때 데이터 양과 epoch를 함께 변경. 상승을 데이터 증가만의 효과라고 단정하지 않기. 99.62점은 64건 학습 자료의 재현 점수로 최종 평가 성능과 비교하면 안 됨. 뒤의 Dev 27.46과 Stage C 27.33은 서로 다른 평가 실행 경로의 결과이며 원인은 완전히 규명되지 않음.

### 간단 대본

> 전체 학습 한 번에 약 6시간이 필요해, 먼저 64건으로 코드가 정상적으로 학습되는지 점검했습니다. 이후 2천 건에서 입력 형식을, 2만 건에서 학습 설정을 비교한 뒤 전체 데이터로 확대했습니다. 단계별 검증 점수는 22.63에서 25.16, 27.33으로 올랐지만, 데이터 외의 조건도 바뀌어 데이터 양만의 효과로 보지는 않았습니다.

## 13페이지. 디코딩 전략: 다음 토큰의 선택 방식

### 핵심 메시지

같은 가중치라도 생성 후보를 고르는 방식에 따라 결과와 시간이 달라짐.

### 용어·수치 설명

- **Greedy:** 매 단계 가장 높은 확률의 토큰 하나를 선택. 앞의 선택을 대안과 함께 유지하지 않음.
- **Beam search:** 여러 부분 요약 후보를 유지하고 누적 점수로 비교. beam 4는 대체로 네 개의 유력한 부분 시퀀스를 유지하는 폭이지 네 번 무작위 요약 후 투표하는 방식이 아님. [공식 생성 전략 문서](https://huggingface.co/docs/transformers/main/en/generation_strategies)
- 점수 25.86 / 26.94 / 27.46, 시간 131 / 167 / 180초. 시간은 검증 1,500건 전체 실행 기준이며 문장당 시간이 아님.
- **no_repeat_ngram_size=3:** 똑같은 연속 토큰 세 개 묶음의 재등장을 금지. 토큰 세 개는 단어 세 개와 다름.
- 정답에도 이런 반복이 13.37% 존재해 정상 정답 생성까지 제한. 0으로 설정해 이 금지 기능 해제.
- 64건 재현 점검에서 97.98→99.62점, 완전 일치하지 않는 출력 12→1건. 이 변화는 필요한 표현을 생성할 수 있게 했다는 점검.

### 알아둘 점

Beam은 확률적으로 유력한 문장을 찾는 탐색이며 참인 문장을 보장하지 않음. 폭을 늘리면 언제나 품질이 높아지는 것도 아님. 반복 금지 해제 후 ‘반복 오류 해결’이라고 주장하면 안 됨.

### 간단 대본

> 같은 모델에서 생성 전략도 비교했습니다. 가장 높은 확률만 따라가는 greedy보다 후보 네 개를 유지하는 beam 4가 1.60점 높아 선택했습니다. 또 반복 금지 규칙이 정답의 정상적인 표현까지 막는 경우가 있어 해제했습니다. 이는 필요한 표현을 허용한 것이며, 반복 오류 자체가 해결됐다는 의미는 아닙니다.

## 14페이지. 최종 성능: 평가 점수의 의미

### 핵심 메시지

같은 요약을 어떤 단위로 평가하는지와, 각 지표가 확인할 수 없는 것을 구분.

### 용어·수치 설명

- **공백 토큰:** 공백으로 나눈 어절. ‘영화를’과 ‘영화가’는 서로 다른 단위.
- **형태소 토큰:** 의미·문법 기능의 더 작은 단위. ‘영화’처럼 공통 부분을 분리해 겹침을 찾기 쉬움. 형태소 점수가 높은 것은 동일 출력의 평가 기준 차이이지 추가 학습 효과가 아님.
- Dev 공백 27.46, 형태소 45.29. 최종 평가 공백 **27.15**, 형태소 **45.35**.
- 최종 평균의 95% 구간: 공백 26.95~27.36, 형태소 45.16~45.54. 개별 대화 점수가 모두 이 안에 있다는 뜻이 아님.
- **자동 점검 97.0%:** 한 문장, 태그, 길이, 키워드, 반복, 종결 형식 등 프로젝트 규칙을 통과한 비율. 정답 자체도 100%가 아닌 규칙이고 사람 사실성 검증과 다름.

### 알아둘 점

27.15점은 27.15%의 요약만 정답이라는 뜻이 아님. Dev와 최종 평가 점수가 가깝다는 사실만으로 과적합 부재를 확정할 수 없음. 27.33→27.46은 학습 직후 평가와 별도 평가 스크립트 경로 차이로 예측이 달라진 기록. bf16만이 원인이라는 가설은 검증에서 지지되지 않았으므로 그렇게 답하지 않기.

### 간단 대본

> 최종 35,004건에서 공백 기준 ROUGE-L은 27.15점, 형태소 기준은 45.35점이었습니다. 같은 요약이라도 형태소 기준은 조사 차이를 덜 엄격하게 보기 때문에 점수가 달라집니다. 자동 점검 통과율은 97%였지만 길이와 형식 같은 규칙의 결과입니다. 이 숫자를 사실 정확도로 해석하지는 않았습니다.

## 15페이지. 최종 선택 모델·학습 설정·평가 성능

### 핵심 메시지

다른 사람이 같은 실험 구성을 이해할 수 있도록 최종 선택 묶음을 정리.

### 용어·내용 설명

| 설정 | 쉬운 뜻 | 오해 방지 |
|---|---|---|
| pko-T5-base | 한국어 사전학습 인코더·디코더 모델 | 요약용 추가 학습 필요 |
| 약 2억 7,560만 파라미터 | 실행 기록에서 보고한 모델 내부 학습 숫자 수 | 토큰 수·학습 문장 수와 다름. 공개 카드의 대략적 모델 크기 표기와 별개 |

### 알아둘 점

모든 값이 최적이라고 입증된 것은 아님. bf16·weight decay의 개별 효과는 비교 미검증. label smoothing 0.0 비교에서도 점수 차이가 명확히 확인된 것은 아니므로 0.1의 우월성을 과장하지 않기.

### 간단 대본

> 최종 선택은 pko-T5-base를 대화 요약에 파인튜닝한 모델입니다. 약 27만 8천 건으로 2회 학습하고 검증 기준 34,000스텝의 모델을 사용했습니다. 입력과 출력은 384와 64토큰, 유효 배치는 16, 생성은 beam 4입니다. 이 구성에서 최종 공백 점수 27.15, 형태소 점수 45.35를 얻었고 학습에는 약 6시간 11분이 걸렸습니다.

## 16페이지. 평균 점수 뒤에 가려진 취약 구간

### 핵심 메시지

전체 평균이 괜찮아도 특정 유형과 길이에서 성능이 떨어질 수 있음.

### 용어·수치 설명

- **슬라이스 평가:** 같은 평가셋을 유형·길이 등의 하위 집단으로 나누어 각각 성능 계산.
- 일상 34,816건, 27.21점. 토론 188건, 16.02점. 차이 **11.19점**.

- 토론에서 여러 의견을 통합하거나 중심 쟁점을 고르는 어려움, 긴 대화에서 잘림·후반 정보 누락은 조사할 가설.

> 전체 평균만으로는 취약한 구간이 가려질 수 있어 데이터를 나눠 봤습니다. 토론은 일상보다 약 11.19점 낮았고, 긴 대화는 짧은 대화보다 7.61점 낮았습니다. 토론의 쟁점 누락과 긴 입력의 잘림 등을 점검할 필요가 있습니다. 다만 이 그래프만으로 원인이나 환각 발생률을 확정할 수는 없습니다.

## 17페이지. 점수 개선과 사실 오류 감소의 관계

### 핵심 메시지

정답 표현을 더 많이 담게 된 것은 관찰됐지만 사실 오류의 지속 감소는 확인하지 못함.

### 용어·수치 설명

- **ROUGE-L 0점 비율:** 선택한 평가 토큰화 기준에서 정답과 겹침을 찾지 못한 사례 비율. 19.0→15.2→13.0%, 6.0%p 감소. 의미가 전혀 같지 않다는 사람 판정과는 다름.
- **정답 내용어 포함률:** 정답의 의미 중심 어휘가 생성문에 얼마나 포함되는지 보는 보조 신호. 45.4→50.9→54.8%, 9.4%p 상승. 단어 포함이 올바른 관계·화자 연결을 보장하지 않음.
- **10·8·11건:** 고정된 30건에서 학습 단계별로 하나 이상 오류가 있다고 분류한 사례 수. 평가자 자체의 실수 건수가 아니며 전부 환각 건수도 아님. 원 기록은 Claude 단독 평가.

### 알아둘 점

v10의 ‘판정 오류’는 ‘판정에서 확인한 요약 오류 사례’로 말하기. 30건 단계별 평가, pko-T5 100건 분석, KoBART 40건 재검토는 서로 다른 집계. 숫자를 이어 붙여 오류가 줄었다고 그래프로 만들 수 없음.

### 간단 대본

> 학습 규모를 늘리면서 ROUGE 0점 비율은 줄고 정답 내용어 포함률은 늘었습니다. 정답 표현을 더 많이 담는 방향의 개선은 확인한 것입니다. 하지만 고정 30건을 분류한 기존 평가에서는 오류 사례가 10건, 8건, 11건으로 지속적으로 줄지 않았습니다. 따라서 점수 상승만으로 사실 오류까지 감소했다고 결론 내리지 않았습니다.

## 18페이지. 오류 판정 기준과 재판정 대상

### 핵심 메시지

좋지 않은 요약을 모두 환각으로 묶지 않고, 사실 왜곡·없는 주장·누락·보류를 구분.

### 용어·내용 설명

- **S, supported:** 생성문의 핵심 주장을 원문이 지지. 완벽한 요약이라는 종합 품질 평가가 아님.
- **I, intrinsic:** 원문 사실을 반대로 만들거나 날짜·주체·대상·관계를 변경. 예: 22일을 25일로 변경.
- **E, extrinsic:** 원문에 없는 별도의 사건·사실 추가. 예: 취소비가 있다는 말만 있는데 실제로 냈다고 추가.
- **B, both:** 독립적으로 식별되는 I와 E가 동시에 존재. 숫자 하나가 바뀌었다는 이유만으로 I와 E를 중복 표시하지 않는 것이 이번 재검토 기준.
- **U, unclear:** 주어 생략·애매한 표현 등으로 확정 어려움. 정상으로 치환하지 않음.
- **누락 Y/N:** 중심 내용 생략 여부. S와 Y가 동시에 가능.

왼쪽은 pko-T5 Dev 고정 100건의 Claude 단독 분류: 미검출 67건, 하나 이상 오류 33건, 그중 사실 오류 15건. 오른쪽은 별도 KoBART 고위험 40건에 대한 A/B 사람 독립 판정 후 AI 재검토. 대상 모델·표본·판정자가 다름.

### 알아둘 점

KoBART를 쓴 이유는 원문과 생성문을 대조할 수 있는 저장 결과가 당시 준비돼 있었기 때문. pko-T5보다 좋은 평가 대상이라는 실험적 근거는 없음. 현재는 보조 사례 분석으로 설명하고, 최종 pko-T5 검증의 공백을 인정하는 것이 정확.

### 간단 대본

> 오류는 원문 사실을 바꾸는 내재적 환각, 없는 사실을 추가하는 외재적 환각, 그리고 핵심 누락으로 구분했습니다. 짧거나 어색하다는 이유만으로 모두 환각으로 보지는 않았습니다. 기존 pko-T5의 100건 분석과 별도로, 뒤의 40건은 저장된 KoBART 출력을 활용한 보조 분석입니다. 두 사람의 독립 판정 이후에는 AI로 원문을 재대조했습니다.

## 19페이지. 실패 사례: 원문 사실의 왜곡 양상

### 핵심 메시지

원문과 어떤 지점에서 모순되는지는 관찰 가능하지만, 모델 내부에서 왜 그런 계산을 했는지는 추가 실험 필요.

### 사례 해설

1. **2층도 괜찮음 → 2층은 싫음:** 질문 ‘2층도?’에 ‘응’이라고 답하고 입장만 해도 좋다고 덧붙였는데 부정으로 요약. 긍정·부정 반전이 직접 확인됨.
2. **4월 22일 → 4월 25일:** 원문의 확인된 날짜와 생성 날짜가 다름. 같은 사건의 수치 변경으로 I 분류. 숫자가 어휘집에 없어서 틀렸다고 단정할 근거는 없음.
3. **코로나 가능성 → 코로나 때문:** 더위·공황 등 여러 가능성을 언급하는 대화를 특정 원인 확정으로 변경. 증상의 실제 의학적 원인을 판정하는 것이 아니라 원문에서의 확실성 수준을 비교.

### 알아둘 점

‘짧은 응답 연결 실패’, ‘날짜 보존 실패’, ‘불확실성 소실’은 출력의 오류 양상과 원인 가설. 특정 attention head나 토크나이저가 원인이라고 밝혀진 것은 아님. 질문·응답 묶기, 수치 검증, 양태 보존 학습은 아직 실험 제안.

### 간단 대본

> 첫 사례는 2층도 괜찮다는 답을 싫다고 반대로 만들었고, 두 번째는 방문 날짜 22일을 25일로 바꿨습니다. 세 번째는 여러 가능성 중 코로나를 확정 원인으로 표현했습니다. 원문과의 불일치는 확인했지만 내부 원인은 가설 단계입니다. 질문과 응답 연결, 수치 대조, 추측 표현 보존을 각각 개선 실험으로 검토할 수 있습니다.

## 20페이지. 2인 독립 판정 후 재검토 결과

### 핵심 메시지

독립 판정도 일치하지 않을 수 있어, 근거와 기준을 명시한 재검토가 필요.

### 수치 읽는 방법

| 항목 | 의미 |
|---|---|
| A: S11 I21 E2 B3 U3 | 사람 A의 40건 독립 판정 |
| B: S11 I18 E1 B9 U1 | 사람 B의 40건 독립 판정 |
| 통합 재검토: S7 I25 E0 B1 U7 | AI가 A/B 근거를 참고해 원문과 대조한 결과 |
| 26/40 = 65.0% | 전체 선택 표본에서 AI가 사실 오류로 분류한 비율 |
| 26/33 = 78.8% | U7건 제외 후 판정 가능 사례 중 비율 |
| 24/36 = 66.67% | 어느 한쪽이라도 U인 4건 제외 후 인간 A/B의 환각 유무 일치 |
| κ = 0.2145 | 우연히 일치할 가능성을 보정한 인간 A/B 일치도 |

**Cohen’s κ:** `(실제 일치율 − 우연 기대 일치율) / (1 − 우연 기대 일치율)`. 1은 완전 일치, 0은 주변 분포로 예상되는 우연 수준, 음수는 그보다 낮은 일치. 여기서 0.2145를 정확도 21.45%로 해석하지 않기. 표본이 작고 범주 분포의 영향을 받으므로 하나의 형용사로 평가자 품질을 단정하지 않음.

### 반드시 알아둘 점

‘팀원 검토 기준 사실 오류’는 현재 출처와 맞지 않는 표현. 26건은 AI 재검토 기준으로 설명. 인간 A도 오류 총수는 26이지만 A의 보류는 3건으로 분모가 37이며 구성도 다름. 숫자가 같다고 같은 판정 결과가 아님. 재검토 열은 독립적인 세 번째 평가가 아니고 인간 합의도 아님. 고위험 표본이라 전체 모델의 환각률을 추정할 수 없음.

### 간단 대본

> 두 사람의 독립 판정 후 원문 근거를 AI로 다시 대조한 결과입니다. 재검토에서는 사실 오류 26건, 원문 지지 7건, 보류 7건으로 분류했습니다. 전체 표본 기준은 65%이고, 보류를 제외하면 78.8%로 분모가 달라집니다. 사람 간 환각 유무 일치도는 66.67%였습니다. 이 결과는 고위험 사례 분석이며 인간 최종 합의나 전체 모델의 환각률을 뜻하지 않습니다.

## 21페이지. 사실 오류와 누락을 구분한 원문 대조

### 핵심 메시지

‘사실이 틀림’과 ‘사실은 맞지만 충분히 요약하지 못함’을 분리해야 오류 원인과 개선 방향도 구체화 가능.

### H012 읽는 순서

1. 빨간 원문: 걷기 좋다는 평가, 춥다는 상대 반응.
2. 초록 원문: 햇빛 드는 곳은 덥다는 주장.
3. 생성문: 초록 주장만 두 번 반복. 빨간 내용은 빠짐.
4. 판정: 원문과 모순된 사실을 만들지는 않아 S. 대화의 중요한 반응을 놓쳐 누락 Y, 동일 내용 반복은 별도 품질 문제.

‘덥지만 덥다’는 연결이 어색하므로 좋은 요약은 아님. 그러나 어색함과 환각은 동일 범주가 아님. 원문의 ‘춥다’와 ‘햇빛 드는 곳은 덥다’도 상황·화자가 달라 함께 존재할 수 있음.

### H018 읽는 순서

1. ‘나만 마스크 안씀’은 적어도 한 사람이 안 썼다는 사실을 포함.
2. ‘마스크를 안 쓴 사람이 있다’는 생성문은 이 사실로 지지됨.
3. 본인을 특정하지 않은 것은 정보의 일반화·생략이며, 다른 사람으로 잘못 지목한 화자 모순과 다름.
4. 뒤의 다른 사람 착용 모습에 대한 반응은 요약에서 빠짐. 그 부분을 중요 논점으로 보고 누락 Y를 부여한 것이 AI의 판단.

### 알아둘 점

S는 ‘정상 품질 보증’이 아니라 원문 지지 라벨. 누락의 중요도는 판단 차이가 있을 수 있으므로 객관적 정답 확정처럼 말하지 않기. 원문에 이미지 실물이 없으므로 방독면 등 특정 물체를 임의로 상정하지 않음. 두 사람 모두 I였지만 AI가 S로 바꾼 사례이므로 ‘사람이 합의해 오판을 수정했다’는 서술은 불가.

### 간단 대본

> 왼쪽은 햇빛 드는 곳이 덥다는 사실을 두 번 말했지만, 걷기 좋다는 평가와 춥다는 반응을 빠뜨렸습니다. 따라서 반복과 누락 문제로 구분했습니다. 오른쪽도 ‘나만 마스크를 안 썼다’면 ‘안 쓴 사람이 있다’는 말은 성립합니다. 누가 안 썼는지와 다른 사람에 대한 반응은 생략됐지만, 반대 사실을 생성한 것은 아니라는 재검토 근거입니다.

## 22페이지. 재검토 오류 유형과 개선 실험

### 핵심 메시지

AI가 사실 오류로 분류한 26건에서 어떤 양상이 많았는지 파악해 다음 실험의 우선순위 설정.

### 용어·수치 설명

- 숫자·개체·시간 12건, `12/26=46.2%`.
- 관계·인과·수식 11건, `11/26=42.3%`.
- 추측·계획의 사실 단정 9건, 의미·극성·구어 표현 7건, 화자 혼동 4건.
- **개체:** 인물·장소·상품 등 구별 가능한 대상. **극성:** 긍정/부정 방향. **수식 관계:** 어떤 속성이 누구·무엇에 붙는지의 관계.
- **다중 라벨:** 한 사례가 수치와 화자를 동시에 틀리면 두 유형에 포함. 합계 43은 고유 오류 사례 수 26과 다름.
- **오탐:** 사실상 문제가 없는 요약을 오류로 잡는 것. 검사 규칙을 엄격하게 하면 오류 탐지와 함께 오탐도 늘 수 있음.

### 검증 설계

수치 검사는 숫자의 존재 여부만 보지 말고 연결된 날짜·대상까지 대조. 화자 태그는 유지/제거 외의 조건을 같게 두고 비교. 인과·추측 보존은 주장 단위로 원문 근거를 확인. 분석한 40건은 개발 사례로 사용하고, 일반화 검증에는 별도 미사용 평가셋을 고정해 오류·누락·오탐·ROUGE를 함께 측정.

### 알아둘 점

이 분포는 ‘어떤 유형으로 틀렸는가’이지 ‘어떤 대화 유형에서 더 자주 환각이 났는가’의 발생률은 아님. 후자를 알려면 예를 들어 숫자가 있는 대화 전체 중 오류 건수처럼 각 조건의 전체 분모 필요. 원래 A/B는 의미·극성 항목을 가장 많이 표시했지만 재검토는 분류 기준이 구체화돼 숫자·개체 항목이 최다. 모델 변화가 아니라 판정 차이.

### 간단 대본

> AI 재검토의 사실 오류 26건에서는 숫자·개체·시간 왜곡이 12건으로 가장 많고, 관계와 인과 연결 오류가 11건이었습니다. 한 사례에 여러 유형이 붙으므로 막대 합계는 사례 수보다 큽니다. 다음 실험에서는 수치와 대상의 연결, 추측 표현, 화자 정보를 우선 점검하되, 오류 감소뿐 아니라 정상 요약의 오탐과 핵심 누락도 함께 비교해야 합니다.

## 23페이지. 결론과 남은 한계

### 핵심 메시지

모델과 설정 선택의 근거는 확보했지만, 신뢰할 수 있는 자동 요약 서비스로 확정하기 위한 검증은 남음.

### 용어·내용 설명

- **seed:** 데이터 순서·초기 난수·dropout 등 무작위 과정의 시작 상태를 정하는 값. 한 seed의 성능이 모든 재학습 결과를 대표하지 않음.
- **holdout:** 개발·선택에 사용하지 않고 남겨 둔 평가 데이터. 기존 최종 평가에서 발견한 문제를 참고해 개선했다면 새 미사용 평가셋으로 확인 필요.
- 확인한 내용: 표현 보존, 제한된 예산에서 전이학습의 효과, 단계별 지표 향상, 생성 전략 선택, 최종 평가 점수.
- 미확인 내용: pko-T5 인간 사실성 평가, 구조만의 인과 효과, seed 변동, 긴 대화 오류 원인, 개선 후 독립 평가 성능.

### 알아둘 점

23페이지에서 삭제된 한계가 해결된 것은 아님. 발표 마무리에는 ‘최종 선택’이 현재 실험 후보 중의 선택이라는 점을 유지. ‘환각 문제 해결’, ‘오류 없는 모델’ 대신 다음 검증 과제를 제시. +16.71은 약16.7로 말하면 9페이지 표시값과 충돌하지 않음.

### 간단 대본

> 이번 실험에서는 표현 보존, 전이학습, 학습 설정과 생성 전략을 비교해 pko-T5를 선택했습니다. 최종 점수는 공백 기준 27.15, 형태소 기준 45.35였습니다. 다만 점수 향상이 사실 오류 감소를 보장하지는 않았고, 오류 분석의 일부는 별도 KoBART 사례였습니다. 다음 단계는 최종 pko-T5의 사람 평가와, 개선 후 미사용 평가셋에서의 재검증입니다.

## 예상 질문과 짧은 답변

**왜 384토큰인가요?**

입력 분포에서 99.44%를 보존하면서 메모리를 고려한 설정입니다. 전처리 후에는 99.66%를 포함했습니다. 모든 길이를 재학습해 최적값을 증명한 결과는 아닙니다.

**UNK 0%면 제일 좋은 토크나이저인가요?**

표현할 수 있는 범위의 장점이지 의미 이해의 증거는 아닙니다. 바이트 기반 설계 특성과 토큰 수·속도도 함께 봐야 합니다.

**왜 더 무거운 pko-T5를 골랐나요?**

이번 모델 비교에서 약 7.92점 높아 성능을 우선했습니다. 다만 시간·메모리 비용과 비교 조건의 차이를 인정합니다.

**전이학습과 파인튜닝은 다른 실험인가요?**

전이학습은 기존 지식을 활용한다는 큰 개념이고, 파인튜닝은 이번에 그 지식을 요약 데이터로 조정한 방법입니다.

**27.15점이면 성능이 낮은 것 아닌가요?**

정답률이 아니라 특정 토큰화 기준의 표현 겹침 점수입니다. 동일 평가 조건의 기준선과 비교해야 하며, 의미·사실성은 별도로 봐야 합니다.

**27.33과 27.46 중 어느 것이 맞나요?**

Stage 비교는 학습 직후 평가 경로의 27.325이고, 최종 Dev 보고는 별도 평가 스크립트의 27.456입니다. 동일 체크포인트에서도 예측 차이가 있었고 원인은 완전히 규명하지 못했습니다. 같은 표 안에서는 같은 평가 경로끼리 비교했습니다.

**어떤 케이스에서 환각이 제일 많이 발생했나요?**

이번 고위험 40건의 재검토에서는 오류 26건 중 숫자·개체·시간 왜곡이 12건으로 가장 많았습니다. 숫자가 있는 모든 대화의 오류 발생률이나 전체 모델의 최다 위험 조건을 측정한 것은 아닙니다.

**왜 최종 모델과 다른 KoBART를 사람 평가했나요?**

당시 원문과 출력이 함께 저장된 KoBART 결과로 보조 오류 분석을 시작했습니다. 최종 모델 검증을 대체할 수 없어 pko-T5의 생성 결과로 별도 사람 평가가 필요합니다.

**팀원이 최종 합의한 수치인가요?**

아닙니다. A/B는 사람의 독립 판정이고, 통합 재검토는 AI가 근거를 대조해 제안한 결과입니다. 인간 최종 합의로 제시하지 않았습니다.

**환각을 실제로 줄였나요?**

현재는 오류를 분류하고 개선 실험을 제안한 단계입니다. 같은 미사용 평가셋에서 개선 전후 모델의 오류를 비교해야 감소를 주장할 수 있습니다.

**누락을 빼면 모델을 좋게 보이게 하는 것 아닌가요?**

누락을 품질 문제에서 빼는 것이 아니라 사실 오류와 별도 축으로 기록한 것입니다. S이면서 누락 Y인 요약도 좋지 않은 요약일 수 있습니다.

**보류를 빼면 오류율이 커지는 이유는요?**

오류 26건은 그대로인데 분모가 40에서 33으로 줄기 때문입니다. 전체 기준65%와 판정가능 기준78.8%를 함께 보고 보류7건도 공개했습니다.
